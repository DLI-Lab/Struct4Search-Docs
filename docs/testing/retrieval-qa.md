# 검색과 QA 평가 실행

인덱싱한 코퍼스에 평가셋을 태워 검색 지표와 답변 정확도를 측정합니다.

## 실행 전 확인

- 평가 대상 코퍼스가 색인되어 있어야 합니다.
- 검색·답변 서비스가 떠 있어야 합니다.
- 어느 인덱스를 재는지 분명해야 합니다.
- 어느 평가셋을 쓰는지 정해야 합니다.

| 평가셋 | 문서 | 질의 | 쓰는 때 |
|---|---:|---:|---|
| 소규모 | 100 | 100 | 변경 중 빠르게 확인 |
| 전체 코퍼스 | 2,567 | 200 | 병합 전 기준선 비교 |

소규모 평가셋은 검색 공간이 100문서라 실제 규모의 난이도를 보여 주지 않습니다. **성능 판정은 전체 코퍼스 평가셋으로 합니다**([평가셋 구성](eval200.md)).

## 실행

```bash
struct4search-evaluate --run-root <출력 디렉터리> --output-root <결과 디렉터리>
```

평가는 검색·답변 파이프라인을 **그대로 태웁니다.** 평가용 검색 경로를 따로 두지 않으므로, 여기서 나온 값이 실제 서비스 경로의 값입니다.

## 결과 파일

| 파일 | 내용 |
|---|---|
| `retrieval_predictions.query_service.jsonl` | 질의별 검색 결과 |
| `retrieval_scores_per_query.jsonl` | 질의별 검색 점수 |
| `qa_answers.jsonl` | 질의별 답변과 인용 |
| `EVALUATION_RESULTS.json` | 전체 요약 |

## 검색 지표

| 지표 | 뜻 |
|---|---|
| `ndcg_at_k` | 정답 근거가 상위에 있는 정도 |
| `required_recall_at_k` | 필요한 정답 근거를 상위 k에서 몇 %나 찾았는가 |
| `hit_at_k` | 상위 k에 정답 근거가 하나라도 있는가 |
| `minimal_set_success_at_k` | 답하는 데 필요한 최소 근거 집합을 다 찾았는가 |

정답 근거와 검색 결과를 맞출 때는 **원문 청크의 위치가 실제로 겹치는지**를 봅니다. 문서만 같으면 맞은 것으로 치지 않습니다.

## QA 지표

답변은 정답과 필수 claim에 대조해 채점합니다. 문자열이 같은지가 아니라 의미가 같은지를 보되, 필수 claim별 충족 여부는 보수적으로 판정합니다.

| 점수 | 뜻 |
|---|---|
| 4 | 모든 필수 내용이 정확하고 중대한 오류 없음 |
| 3 | 대체로 정확하나 경미한 누락이나 부정확성 |
| 2 | 핵심의 일부만 충족 |
| 1 | 최소한의 관련 내용만 있고 중대한 누락이나 오류 |
| 0 | 오답이거나 무응답 |

정답 범위를 넘어 법적 기준·수치·요건을 단정한 답변은 따로 표시됩니다. 검색이 맞았는데 답변이 과하게 나가는 경우를 잡기 위한 것입니다.

## 인용 검증

답변 결과에는 인용 정리 집계가 함께 남습니다.

| 집계 | 0이 아니면 |
|---|---|
| `duplicate_citations_removed` | 모델이 한 claim 안에서 같은 근거를 반복 |
| `retrieval_expression_citations_removed` | 모델이 검색표현을 인용하려 함 |
| `out_of_context_citations_removed` | 모델이 Context 밖 ID를 인용하려 함 |
| `unsupported_claims_removed` | 근거 없는 문장을 만들어 제거됨 |

네 값이 모두 0이어야 정상입니다. 0이 아니면 프롬프트나 Context 구성을 봅니다.

## 재현성 확인

같은 인덱스, 같은 평가셋, 같은 모델이면 같은 검색 결과가 나옵니다. 두 실행의 검색 결과가 다르면 인덱스나 설정이 그 사이에 바뀐 것입니다.

결과를 기록할 때 **무엇을 쟀는지 함께 남깁니다** — commit, 프로파일, 인덱스 이름, 평가셋 릴리스, 모델([기준 성능과 회귀 판정](regression-gates.md)).

## 실패 질의 확인

`retrieval_scores_per_query.jsonl`에서 점수가 낮은 질의를 골라 `retrieval_predictions.query_service.jsonl`의 같은 질의를 봅니다. 정답 근거가 후보에 아예 없으면 검색 문제이고, 후보에는 있는데 상위에 없으면 순위 문제입니다.
