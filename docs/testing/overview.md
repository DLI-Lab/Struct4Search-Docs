# 테스트 구성과 실행

검증은 크게 두 갈래입니다. 모듈 테스트는 계약이 깨졌는지 보고, E2E 테스트는 전체가 실제로 도는지와 성능이 유지되는지 봅니다.

| 갈래 | 확인하는 것 | 모델·서비스 | 명령 |
|---|---|---|---|
| 모듈 테스트 | 코드 계약과 같은 입력의 같은 동작 | 필요 없음 | `pytest` |
| E2E — 문서 한 건 | 전체 서비스가 연결되어 도는지 | 필요 | `struct4search-smoke-e2e` |
| E2E — 평가셋 | 검색과 답변의 성능 | 필요 | `struct4search-evaluate` |

**모듈 테스트 통과는 계약 검증일 뿐 기능 검증의 완료가 아닙니다.** 프롬프트를 고치면 모듈 테스트는 모두 통과하면서 답변 품질이 떨어질 수 있습니다.

## 모듈 테스트

```bash
pytest
```

모델도 외부 서비스도 없이 돕니다. 영역별 실행과 무엇을 고정하는지는 [테스트 범위](test-levels.md)에 있습니다.

## E2E — 문서 한 건

```bash
struct4search-smoke-e2e
```

고정된 문서 하나로 인덱싱부터 답변까지 통과시킵니다. 별칭을 바꾸거나 서비스를 재시작하지 않으므로 기존 인덱스에 영향이 없습니다. 성능은 재지 않고 **연결이 살아 있는지**만 봅니다.

## E2E — 평가셋

```bash
struct4search-evaluate --run-root <출력 디렉터리> --output-root <결과 디렉터리>
```

평가셋은 두 가지입니다.

| 평가셋 | 문서 | 질의 | 쓰는 때 |
|---|---:|---:|---|
| 소규모 | 100 | 100 | 변경 중 빠르게 확인 |
| 전체 코퍼스 | 2,567 | 200 | 병합 전 기준선 비교 |

구성은 [평가셋 구성](eval200.md), 지표의 의미는 [평가 지표와 검증 방법](metrics.md), 실행과 결과 읽는 법은 [검색과 QA 평가 실행](retrieval-qa.md)에 있습니다.

## 무엇을 언제 돌리는가

| 바꾼 것 | 모듈 테스트 | 문서 한 건 E2E | 평가셋 E2E |
|---|---|---|---|
| 설정 스키마·계약 | 필수 | — | — |
| 서비스 주소·모델 교체 | 필수 | 필수 | 필수 |
| 파싱·청킹·NER·KG 구축 | 필수 | 필수 | 필수 |
| Metadata·검색표현 프롬프트 | 필수 | 필수 | 필수 |
| 검색 파라미터·점수 통합 | 필수 | — | 필수 |
| Context 구성 | 필수 | — | 필수 (QA) |
| 답변 프롬프트·모델 | 필수 | — | 필수 (QA) |
| 동시성 | 필수 | 필수 | — |

**검색만 재고 넘어가지 않습니다.** 검색 지표가 올라도 Context가 바뀌면 답변이 나빠질 수 있습니다.
