# 테스트 구성과 실행

무엇을 확인하려는지에 따라 도구가 다릅니다. 이 페이지에서 그 구분을 정합니다.

## 네 가지가 서로 다른 것을 봅니다

| 구분 | 확인하는 것 | 모델·서비스 필요 |
|---|---|---|
| 테스트 | 코드 계약과 같은 입력의 같은 동작 | 없음 |
| 문서 한 건 E2E | 전체 서비스가 연결되어 실제로 도는지 | 필요 |
| 검색 평가 | 정답 근거가 검색되는지 | 필요 |
| QA 평가 | 검색된 근거로 올바른 답변과 인용을 만드는지 | 필요 |

**테스트 통과는 계약 검증일 뿐 기능 검증의 완료가 아닙니다.** 프롬프트를 고치면 테스트는 모두 통과하면서 답변 품질이 떨어질 수 있습니다.

## 테스트 실행

```bash
pytest
```

모델도 외부 서비스도 없이 돕니다. 테스트 구성은 [테스트의 세 층](test-levels.md)에 있습니다.

## 문서 한 건 E2E

```bash
struct4search-smoke-e2e
```

고정된 문서 하나로 인덱싱부터 답변까지 통과시킵니다. 별칭을 바꾸거나 서비스를 재시작하지 않으므로 기존 인덱스에 영향이 없습니다.

## 평가 실행

```bash
struct4search-evaluate --run-root <출력 디렉터리> --output-root <결과 디렉터리>
```

평가셋 구성은 [평가셋 구성](eval200.md), 지표와 결과 읽는 법은 [검색과 QA 평가 실행](retrieval-qa.md)에 있습니다.

## 무엇을 언제 돌리는가

| 바꾼 것 | 테스트 | 검색 평가 | QA 평가 |
|---|---|---|---|
| 설정 스키마·계약 | 필수 | — | — |
| 파싱·청킹·NER·KG 구축 | 필수 | 필수 | 필수 |
| Metadata·검색표현 프롬프트 | 필수 | 필수 | 필수 |
| 검색 파라미터·점수 통합 | 필수 | 필수 | 필수 |
| Context 구성 | 필수 | — | 필수 |
| 답변 프롬프트·모델 | 필수 | — | 필수 |
| 동시성·서비스 주소 | 필수 | — | — |

**검색만 재고 넘어가지 않습니다.** 검색 지표가 올라도 Context가 바뀌면 답변이 나빠질 수 있습니다.
