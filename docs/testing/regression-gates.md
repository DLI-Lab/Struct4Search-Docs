# 기준 성능과 회귀 판정

변경 전후를 비교할 기준선을 정하고, 변경 사항을 병합해도 되는지 판정합니다.

## 기준선은 값 하나가 아닙니다

측정값만으로는 같은 조건에서 결과를 재현할 수 없습니다. 기준선을 기록할 때는 다음 정보를 함께 남깁니다.

| 항목               | 이유                                                      |
| ---------------- | ------------------------------------------------------- |
| 코드 commit        | 단계 구현에 따라 결과가 달라집니다                                     |
| 실행 프로파일          | 임계값·모델·자원 설정이 포함됩니다                                     |
| 인덱스 이름과 생성 시각    | 어떤 색인을 평가했는지 구분합니다                                      |
| 평가셋 릴리스          | 소규모(100/100)와 대규모(2,567/200) 중 어떤 평가셋과 릴리스를 사용했는지 구분합니다 |
| 문서 전처리 모델과 답변 모델 | 전처리와 답변 생성의 영향을 구분합니다                                   |
| 측정 날짜            | 평가 시점을 기록합니다                                            |

앞의 다섯 항목 중 하나라도 다르면 같은 조건의 기준선으로 비교하지 않습니다.

기준선은 **대규모 평가셋(2,567문서·200질의)** 으로 측정합니다. 소규모 평가셋은 변경 중 성능 방향을 빠르게 확인하는 용도로 사용하며, 병합 판정의 기준선으로 사용하지 않습니다.

## 회귀 판정 기준

* 모듈 테스트가 모두 통과해야 합니다.
* 검색 지표가 기준선보다 낮아지면 병합하지 않습니다.
* QA 정확도가 기준선보다 낮아지면 병합하지 않습니다.
* 인용 정리 집계가 `0`이 아니면 실패로 판정합니다.
* 평가 결과에는 commit·프로파일·모델·인덱스·평가셋 릴리스를 함께 기록합니다.

인용 정리 집계가 `0`이 아니라는 것은 모델 출력에 인용 계약을 벗어난 항목이 있었고, 후처리 과정에서 이를 제거했다는 뜻입니다. 최종 답변에서 제거됐더라도 원인이 남아 있으므로 정상 결과로 보지 않습니다.

## 무엇을 바꿨을 때 무엇을 다시 재는가

| 바꾼 것               | 검색 평가 | QA 평가 |
| ------------------ | ----- | ----- |
| 파싱·청킹·NER·KG 구축    | 필수    | 필수    |
| Metadata·검색표현 프롬프트 | 필수    | 필수    |
| 검색 파라미터·점수 통합      | 필수    | 필수    |
| Context 구성         | —     | 필수    |
| 답변 프롬프트·모델         | —     | 필수    |
| 동시성·서비스 주소         | —     | —     |

검색이나 답변에 영향을 주는 변경은 필요한 평가 범위를 함께 확인합니다. 검색 지표가 좋아져도 Context가 달라지면 최종 답변 품질은 낮아질 수 있습니다.

## 구성을 둘 이상 운영할 때

문서 전처리 모델을 둘 이상 운영한다면 **구성별 기준선을 따로 유지합니다.** 한 구성의 기준선으로 다른 구성을 비교하면 모델 차이가 회귀로 잘못 해석될 수 있습니다.

## 기준선을 다시 잡아야 하는 때

| 상황            | 이유               |
| ------------- | ---------------- |
| 평가셋 릴리스가 바뀜   | 평가 자산이 달라집니다     |
| 인덱스를 새로 만듦    | 검색 대상이 달라집니다     |
| 문서 전처리 모델을 바꿈 | 검색 대상 데이터가 달라집니다 |

이 경우에는 새 조건에서 성능을 다시 측정하고 새로운 기준선으로 사용합니다.
