# 테스트 범위

검증은 크게 **모듈 테스트**와 **E2E 테스트** 두 갈래입니다. 무엇을 확인하려는지에 따라 고르면 됩니다.

| 갈래 | 확인하는 것 | 모델·서비스 | 소요 |
|---|---|---|---|
| 모듈 테스트 | 코드 계약과 같은 입력의 같은 동작 | 필요 없음 | 짧음 |
| E2E 테스트 | 전체가 연결되어 실제로 도는지, 성능이 유지되는지 | 필요 | 김 |

## 모듈 테스트

모델도 외부 서비스도 없이 돕니다. 계약이 깨졌는지만 봅니다.

```bash
pytest
```

### 무엇을 고정하는가

| 영역 | 고정하는 것 |
|---|---|
| 설정 | 프로파일 스키마, 고정 리터럴, 프롬프트·파이프라인 해시 |
| 인덱싱 단계 | 단계별 산출물 형태와 조립 |
| 검색·답변 | 점수 통합 순서와 결정성, 인용 정리 |
| 평가 | 평가 자산 해석과 지표 계산 |

### 영역별 실행

```bash
pytest tests/unit/query      # 검색·답변 경로 계약
pytest tests/unit/ingest     # 인덱싱 단계 조립
pytest tests/unit/config     # 프로파일과 프롬프트 고정
pytest tests/test_config_contracts.py   # 설정값 계약
```

전부 돌려도 짧게 끝나므로, 무엇을 골라야 할지 애매하면 `pytest`를 그냥 돌립니다.

### 모듈 테스트가 잡지 못하는 것

같은 입력에 같은 동작을 고정할 뿐, **답변이 더 나은지 나쁜지는 판단하지 않습니다.** 프롬프트를 고치면 모듈 테스트는 모두 통과하면서 답변 품질이 떨어질 수 있습니다.

## E2E 테스트

실제 서비스를 붙여 돌립니다. 두 종류입니다.

### 문서 한 건 E2E

```bash
struct4search-smoke-e2e
```

고정된 문서 하나로 인덱싱부터 답변까지 한 번 통과시킵니다. 별칭을 바꾸거나 서비스를 재시작하지 않으므로 기존 인덱스에 영향이 없습니다.

**연결이 살아 있는지**를 보는 것이 목적입니다. 성능은 재지 않습니다. 서비스 설정을 바꿨거나 모델을 교체했을 때 가장 먼저 돌립니다.

### 평가셋 E2E

```bash
struct4search-evaluate --run-root <출력 디렉터리> --output-root <결과 디렉터리>
```

평가셋으로 검색과 답변을 돌려 지표를 냅니다. 평가셋은 두 가지이고 목적이 다릅니다([평가셋 구성](eval200.md)).

| 평가셋 | 문서 | 질의 | 쓰는 때 |
|---|---:|---:|---|
| 소규모 | 100 | 100 | 변경 중 빠르게 확인 |
| 전체 코퍼스 | 2,567 | 200 | 병합 전 기준선 비교 |

성능 판정은 전체 코퍼스 평가셋으로 합니다. 소규모 평가셋은 검색 공간이 100문서라 실제 규모의 난이도를 보여 주지 않습니다.

## 무엇을 고쳤을 때 무엇을 돌리는가

| 고친 곳 | 모듈 테스트 | 문서 한 건 E2E | 평가셋 E2E |
|---|---|---|---|
| 설정 스키마·계약 | 필수 | — | — |
| 서비스 주소·모델 교체 | 필수 | 필수 | 필수 |
| 파싱·청킹·NER·KG 구축 | 필수 | 필수 | 필수 |
| Metadata·검색표현 프롬프트 | 필수 | 필수 | 필수 |
| 검색 파라미터·점수 통합 | 필수 | — | 필수 |
| Context·답변 프롬프트 | 필수 | — | 필수 (QA) |
| 동시성 | 필수 | 필수 | — |
