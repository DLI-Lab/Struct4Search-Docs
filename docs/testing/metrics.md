# 평가 지표와 검증 방법

평가가 내는 값이 각각 무엇을 재는지, 어떤 기준으로 맞았다고 판정하는지 정리합니다. 실행 방법은 [검색과 QA 평가 실행](retrieval-qa.md)에 있습니다.

## 검색 지표

| 지표 | 재는 것 |
|---|---|
| `ndcg_at_k` | 정답 근거가 상위에 있는 정도 |
| `required_recall_at_k` | 필요한 정답 근거를 상위 k에서 몇 %나 찾았는가 |
| `hit_at_k` | 상위 k에 정답 근거가 하나라도 있는가 |
| `minimal_set_success_at_k` | 답하는 데 필요한 최소 근거 집합을 다 찾았는가 |

`hit`은 하나만 맞아도 참이고 `minimal_set_success`는 필요한 근거를 다 찾아야 참입니다. 두 값이 벌어지면 **일부만 찾고 있다**는 뜻입니다.

## 맞았다는 판정 기준

검색 결과와 정답 근거를 맞출 때는 **원문 청크가 가리키는 위치가 실제로 겹치는지**를 봅니다.

문서만 같으면 맞은 것으로 치지 않습니다. 같은 문서의 엉뚱한 쪽을 가져와도 문서 단위로는 정답처럼 보이지만, 그 근거로는 답할 수 없기 때문입니다.

## QA 채점

답변은 정답과 필수 claim에 대조해 채점합니다. 문자열이 같은지가 아니라 **의미가 같은지**를 보되, 필수 claim별 충족 여부는 보수적으로 판정합니다.

| 점수 | 뜻 |
|---|---|
| 4 | 모든 필수 내용이 정확하고 중대한 오류 없음 |
| 3 | 대체로 정확하나 경미한 누락이나 부정확성 |
| 2 | 핵심의 일부만 충족 |
| 1 | 최소한의 관련 내용만 있고 중대한 누락이나 오류 |
| 0 | 오답이거나 무응답 |

정답 범위를 넘어 법적 기준·수치·요건을 단정한 답변은 따로 표시됩니다. **검색은 맞았는데 답변이 과하게 나가는 경우**를 잡기 위한 것입니다.

## 인용 검증

지표와 별개로, 답변이 인용 계약을 지켰는지를 집계로 확인합니다.

| 집계 | 0이 아니면 |
|---|---|
| `duplicate_citations_removed` | 한 claim 안에서 같은 근거를 반복 |
| `retrieval_expression_citations_removed` | 검색표현을 인용하려 함 |
| `out_of_context_citations_removed` | Context 밖 ID를 인용하려 함 |
| `unsupported_claims_removed` | 근거 없는 문장을 만들어 제거됨 |

네 값이 모두 0이어야 정상입니다. 값이 0이 아니어도 후처리가 지우므로 답변은 멀쩡해 보이지만, **원인은 남아 있습니다.**

## 지표를 함께 읽는 법

| 상황 | 읽는 법 |
|---|---|
| 검색 지표가 낮음 | 근거가 아예 검색되지 않음. 인덱싱 쪽을 봅니다 |
| 검색은 높은데 QA가 낮음 | 근거는 찾았으나 답변이 잘못됨. Context와 답변 프롬프트를 봅니다 |
| QA는 높은데 인용 집계가 0이 아님 | 답변은 맞았으나 계약을 어김. 프롬프트를 봅니다 |
| `hit`은 높은데 `minimal_set_success`가 낮음 | 근거를 일부만 찾음. 최종 근거 수와 후보 폭을 봅니다 |
