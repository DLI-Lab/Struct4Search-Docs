# 평가셋

평가셋은 같은 문서와 질문으로 검색·답변 품질을 반복해서 비교하기 위한 자료입니다. 질문만 모아 둔 파일이 아니라, 질문마다 찾아야 할 문서, 답변에 반드시 들어가야 할 내용과 그 내용을 확인한 원문 위치를 함께 보관합니다.

평가 자료는 Git 저장소에 포함되지 않습니다. 원본 문서와 정답 근거가 있는 서버에서 환경변수로 위치를 지정해 사용합니다.

## 평가셋 종류

| 평가셋 | 구성 | 질문 범위 | 사용하는 경우 |
|---|---|---|---|
| 100문서 평가셋 | 고정 문서 100건·질문 100건 | 단일 페이지 75건, 여러 문서 25건 | 코드·모델·검색 설정을 바꾼 뒤 전체 평가 전에 빠르게 확인 |
| 전체 문서 평가셋 | 문서 2,567건·질문 200건 | 단일 페이지 146건, 여러 페이지 13건, 여러 문서 41건 | 전체 코퍼스의 최종 검색·답변 품질과 회귀 확인 |

두 평가는 운영 검색 데이터와 분리된 공간에 문서를 새로 인덱싱합니다. 평가가 끝났다고 운영 검색 결과가 자동으로 바뀌지는 않습니다.

## 전체 200개 질문의 범위

전체 평가셋은 짧은 사실 확인만 측정하지 않습니다. 원문에서 수치 하나를 찾는 질문부터 여러 페이지나 여러 문서의 절차를 합쳐야 하는 질문까지 포함합니다.

### 답변 형태

| 주된 질문 유형 | 질문 수 | 예 |
|---|---:|---|
| 서술형 | 28 | 작업 전에 준비해야 할 절차를 설명하는 질문 |
| 원문 추출형 | 28 | 문서에 적힌 기준이나 문구를 찾는 질문 |
| 비교형 | 28 | 두 조건이나 방법의 차이를 설명하는 질문 |
| 참·거짓형 | 28 | 특정 조치가 허용되는지 판단하는 질문 |
| 수치형 | 28 | 압력, 농도, 시간과 같은 정확한 값을 묻는 질문 |
| 여러 근거 결합 | 32 | 떨어진 페이지나 문서의 내용을 합쳐야 하는 질문 |
| 목록형 | 28 | 빠뜨리지 않고 여러 항목을 제시해야 하는 질문 |

질문 표현도 한 가지로 고정하지 않았습니다. 일반적인 질문 133건, 작업 지시 형태 36건, 검색어처럼 짧은 표현 31건으로 구성되어 있습니다. 원문 근거는 text 195건, infographic 6건, table 5건을 포함하며 한 질문이 여러 형식을 함께 사용할 수 있습니다.

전체 200개 질문은 166개의 필수 문서와 350개의 원문 근거를 사용합니다. 모든 질문은 원본 PDF에서 근거를 다시 확인했고, 질문 ID는 `q001`부터 `q200`까지 중복 없이 이어집니다.

## 평가셋을 만든 방법

각 질문은 다음 순서로 만듭니다.

1. 산업안전 문서에서 실제로 물을 수 있는 작업 절차, 기준, 수치나 비교 항목을 고릅니다.
2. 원본 PDF를 열어 답을 뒷받침하는 문장, 표 또는 그림의 위치를 확인합니다.
3. 정답 문서와 원문 근거를 기록하고, 정답을 이루는 필수 내용을 `c1`, `c2`처럼 나눕니다.
4. 질문이 한 페이지로 충분한지, 여러 페이지 또는 여러 문서를 함께 찾아야 하는지 표시합니다.
5. 검색 난이도, 질문 유형과 근거 형식을 기록합니다.
6. 답할 수 있는 질문인지, 모든 필수 내용에 근거가 있는지와 원본 확인이 끝났는지 검사합니다.

여러 근거가 필요한 질문은 한 근거만으로도 답할 수 없는지 별도로 확인합니다. 이 검사를 통과해야 여러 페이지 또는 여러 문서 질문으로 승인됩니다. 전체 평가셋의 구조 검사 결과는 오류 0건, 경고 0건이며 최종 상태는 `approved`입니다.

## 실제 질문 예시

다음은 전체 평가셋의 `q001`입니다.

| 항목 | 내용 |
|---|---|
| 질문 | 질소를 사용한 교반기에서 첨가제를 투입하려면 어떻게 준비해야 하나요? |
| 범위 | 같은 문서의 서로 다른 두 페이지를 함께 찾아야 하는 질문 |
| 필수 문서 | 교반기 첨가제 투입 중 질식 사고와 예방조치를 설명한 문서 1건 |
| 필수 내용 1 | 맨홀 개방 전에 잔류압력을 확인하고 내부를 충분히 환기합니다. |
| 필수 내용 2 | 개방한 뒤 산소농도가 18% 이상 23.5% 미만인지 확인합니다. |
| 필수 내용 3 | 적정공기를 확인하기 전에는 접근하지 않고 작업 감시, 절차와 교육을 함께 시행합니다. |
| 정답 예시 | 맨홀 개방 전 잔류압력이 없는지 확인하고 내부를 충분히 환기한다. 개방 직후 교반기 내부와 투입구 주변의 산소를 측정해 18% 이상 23.5% 미만인지 확인한다. 확인 전에는 개구부에 접근하지 않고 작업감시·절차·교육을 병행한다. |

이 질문은 다음처럼 평가됩니다.

1. 실제 검색 결과에 필수 문서가 몇 번째로 나타나는지 확인합니다.
2. Reader는 최종 검색 근거만 사용해 답변과 Citation을 만듭니다.
3. 독립 답변 평가자는 생성된 답변이 위 세 가지 필수 내용을 충족하는지, 반대되는 내용이나 근거를 벗어난 단정이 있는지 확인합니다.
4. 세 내용을 정확히 충족하면 `2`, 일부만 충족하거나 중요한 오류가 있으면 `1`, 오답이나 무응답이면 `0`으로 기록합니다.

## 질의부터 점수까지의 흐름

### 1. 질의와 검색

`queries.jsonl`의 질문을 실제 `QueryService`에 보냅니다. QueryService는 질의를 Embedding으로 바꾸고 Hybrid 검색과 RRF를 실행한 뒤, 답변에 사용할 최종 원문을 고릅니다.

검색 평가는 최종 원문의 문서 순서를 `qrels.jsonl`의 정답 문서와 비교합니다. 첫 정답 문서가 얼마나 앞에 있는지, 상위 5개·10개 안에서 필요한 문서를 찾았는지와 여러 문서가 필요한 질문에서 필수 문서를 모두 찾았는지를 계산합니다.

### 2. 답변과 Citation

Reader는 최종 원문 근거로 답변을 만들고 각 문장에 사용한 원문 ID를 기록합니다. 평가 실행은 답변, Citation, 최종 원문과 잘못된 Citation을 정리한 횟수를 질문별 파일에 저장합니다.

여기까지의 E2E 검사는 답변이 비어 있지 않고 Citation이 실제 원문과 연결되는지 확인합니다. 이 검사만 통과했다고 답변 내용이 정답이라는 뜻은 아닙니다.

### 3. 독립 답변 평가

답변 내용의 평가는 LLM-as-Judge 방식을 사용합니다. 현재 production 답변 모델은 `Qwen/Qwen3-14B`이며, 공식 답변 평가는 답변 모델과 분리된 `gpt-5.6-terra`가 정답, 필수 내용과 금지된 과도한 단정을 비교하도록 설계되어 있습니다.

`struct4search-evaluate`가 실행 중에 유료 평가 모델을 직접 호출하지는 않습니다. 독립 평가를 별도로 실행한 뒤 다음처럼 질문별 `0·1·2` 점수만 JSONL 파일로 전달합니다.

```json
{"query_id": "q001", "score": 2}
```

evaluator는 모든 질문에 점수가 정확히 하나씩 있는지, 허용된 값인지 검사한 뒤 평균을 계산합니다. 점수가 빠졌거나 `0·1·2` 이외의 값이 있으면 답변 품질 판정을 진행하지 않습니다.

### 4. 변경 전 결과와 비교

검색 점수와 답변 평균은 같은 평가셋으로 만든 변경 전 결과와 비교합니다. 새 결과가 설정한 허용 범위보다 떨어지면 통과하지 않습니다. 평가셋이나 검색 대상 문서를 바꾼 경우에는 이전 점수와 직접 비교하지 않고 새 기준 결과를 만듭니다.

최근 실행 점수는 평가셋의 고정 정보가 아니므로 [테스트와 평가 개요](overview.md#최근-보관된-e2e-결과)에 날짜와 함께 기록합니다.

## 100문서 평가셋 실행

현재 서버에서는 `configs/machine-paths.yaml`에 등록된 경로를 사용합니다. 다른 서버에서는 원본 문서와 평가 자료가 들어 있는 상위 디렉터리를 먼저 지정합니다.

```bash
export S4S_ARTIFACT_TEST_FIXTURE_ROOT=/absolute/path/to/test-fixtures
struct4search-final-100-100-e2e
```

100문서 평가는 다음 고정 파일을 사용합니다. 코드에 기록된 SHA-256이나 파일 구성이 다르면 실행을 시작하지 않습니다.

| 파일 | 내용 |
|---|---|
| `release_manifest.jsonl` | 평가 파일과 해시 목록 |
| `documents.jsonl` | 평가할 100문서 목록 |
| `queries.jsonl` | `q001`부터 `q100`까지의 질문 |
| `qrels.jsonl` | 질문별 정답 문서와 관련도 |
| `answers.jsonl` | 정답 답변 |
| `evidence.jsonl` | 답변 근거 위치 |
| `dataset.jsonl` | 질문별 필수 문서와 답변 항목 |
| `multi_hop_dependencies.jsonl` | 여러 문서가 필요한 질문의 문서 관계 |

## 전체 문서 평가셋 실행

전체 평가 자료가 들어 있는 디렉터리를 지정한 뒤 실행합니다.

```bash
export S4S_ARTIFACT_EVALUATION_ROOT=/absolute/path/to/full-evaluation-set
struct4search-final-full-2567-200-e2e
```

`configs/evaluation-release.json`에는 다음 파일의 이름과 예상 수량이 정의되어 있습니다.

| 파일 | 내용 |
|---|---|
| `corpus_manifest.jsonl` | 검색 대상 2,567문서 |
| `queries.jsonl` | 200개 질문과 질문 유형 |
| `qrels.jsonl` | 질문별 정답 문서, 관련도와 뒷받침하는 필수 내용 |
| `qa_gt.jsonl` | 정답 답변, 필수 내용과 확인한 원문 근거 |
| `gt_documents.jsonl` | 정답 문서 166건의 목록 |
| `dataset.jsonl` | 질문, 검색 정답과 답변 정답을 합친 최종 평가 자료 |
| `VALIDATION_REPORT.json` | 질문 수, 유형, 근거와 원본 확인 결과 |
| `TERRA_ULTRA_FINAL_AUDIT.json` | 평가 자료의 최종 승인 결과 |

실행 전에 문서 2,567건, 질문 200건, qrels 242건, 정답 문서 166건과 원문 근거 350건을 확인합니다. 수량이나 필수 파일이 다르면 평가를 시작하지 않습니다.

## 평가 자료를 변경할 때

질문, 정답 문서, 정답 답변 또는 근거를 수정하면 별도의 새 평가셋으로 보관하고 기준 결과도 다시 만듭니다. 기존 파일을 덮어쓰면 변경 전후 결과를 같은 조건으로 비교할 수 없습니다.
