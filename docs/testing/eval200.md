# 평가셋 구성

검색·QA 평가가 쓰는 고정 자산입니다. 값이 바뀌면 이전 측정과 비교할 수 없으므로 한 곳에서만 해석합니다.

## 릴리스가 선언하는 수

| 항목 | 수 |
|---|---:|
| 문서 | 2,567 |
| 질의 | 200 |
| qrels | 242 |
| 정답 근거를 가진 문서 | 166 |
| 근거 항목 | 350 |

이 값은 `configs/evaluation-release.json`이 선언합니다. 실제 파일이 이 수와 다르면 평가가 시작되지 않습니다.

## 자산 파일

| 파일 | 내용 |
|---|---|
| `corpus_manifest.jsonl` | 평가 대상 문서 목록 |
| `queries.jsonl` | 질의 |
| `qrels.jsonl` | 질의별 정답 근거 |
| `qa_gt.jsonl` | 정답 답변 |
| `dataset.jsonl` | 위를 묶은 마스터 |

파일 위치는 기계별 경로 정의에서 옵니다. 실행기가 자기 경로를 직접 들지 않고 **릴리스 정의 한 곳에서만** 해석하므로, 서로 다른 자산으로 낸 결과를 같은 값처럼 비교하는 일이 생기지 않습니다.

## 질의 하나의 구조

질의는 `query_id`와 질의문을 갖고, `qrels`가 그 질의의 정답 근거를 가리킵니다. 근거는 문서 단위가 아니라 **원문 청크의 위치**로 적혀 있어, 검색 결과가 정답 근거를 실제로 담았는지 판정할 수 있습니다.

질의 수 200에 qrels 242라는 것은 질의 하나가 근거를 여럿 요구하는 경우가 있다는 뜻입니다.

## 수정 규칙

평가셋을 고치면 그 전후의 지표를 비교할 수 없습니다. 다음을 지킵니다.

- 질의나 정답을 바꾸면 **새 릴리스로 만듭니다.** 같은 릴리스 안에서 조용히 고치지 않습니다.
- 선언된 수를 함께 갱신합니다. 파일과 선언이 어긋나면 평가가 거부합니다.
- 기준 성능을 다시 측정합니다. 이전 기준선은 이전 릴리스의 값입니다([기준 성능과 회귀 판정](regression-gates.md)).
