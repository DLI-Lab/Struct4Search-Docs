# 데이터와 인덱스 구조 변경

색인 문서의 필드나 OpenSearch 인덱스 매핑을 변경하는 방법입니다. 기존 검색 데이터와 호환되지 않는 변경은 새 인덱스를 만든 뒤 다시 색인해야 합니다.

## 변경에 따른 영향

| 바꾼 것 | 영향을 받는 것 |
|---|---|
| 색인 문서에 필드 추가 | 기존 문서에는 새 필드 값이 없음 |
| 기존 필드의 타입 변경 | 기존 인덱스 매핑과 호환되지 않음 |
| 벡터 차원 변경 | 기존 임베딩 벡터와 비교할 수 없음 |
| 검색 단위 종류 추가 | 검색과 검색 결과 점수 통합 방식 |
| 청크 ID 구성 변경 | 검색 단위 ID와 이를 참조하는 후속 데이터 |

기존 필드의 타입이나 벡터 차원처럼 현재 인덱스와 호환되지 않는 값을 변경하면 새 인덱스를 만들고 다시 색인합니다.

## 새 인덱스로 전환하기

1. 색인 문서와 매핑을 변경합니다.
2. 새 이름의 인덱스를 만들고 코퍼스를 다시 색인합니다.
3. 새 인덱스로 검색·QA 평가를 실행해 기존 기준선과 비교합니다.
4. 검증이 끝나면 검색에서 사용하는 alias를 새 인덱스로 전환합니다.
5. 이전 인덱스는 전환이 확인된 뒤 삭제합니다.

새 인덱스를 먼저 검증한 뒤 alias를 전환하면 문제가 있을 때 이전 인덱스로 되돌릴 수 있습니다.

## 검색 단위 종류를 추가할 때

현재 검색 단위는 두 종류입니다.

| `unit_kind` | 의미 |
|---|---|
| `source` | 원문 청크 |
| `retrieval_expression` | 검색표현 |

새로운 검색 단위를 추가하려면 다음을 함께 정해야 합니다.

- 어떤 텍스트와 벡터를 색인할지
- 어떤 원문 청크와 연결할지
- 검색되었을 때 점수를 어떻게 처리할지
- 최종 답변에서 Citation으로 사용할 수 있는지

현재 답변의 Citation에는 원문 청크만 사용할 수 있습니다. 새로운 검색 단위를 인용 가능하게 만들려면 검색 결과 처리뿐 아니라 답변과 Citation 계약도 함께 변경해야 합니다.

## 되돌리기

| 상황 | 되돌리는 방법 |
|---|---|
| alias 전환 전 | 새 인덱스를 사용하지 않고 기존 인덱스를 유지합니다 |
| alias 전환 후 | 이전 인덱스가 남아 있으면 alias를 다시 이전 인덱스로 전환합니다 |
| 이전 인덱스 삭제 후 | 이전 인덱스를 다시 색인해야 합니다 |

따라서 새 인덱스의 검색·QA 검증이 끝나기 전에는 이전 인덱스를 삭제하지 않습니다.

## 코드 참조

| 확인할 내용 | 파일·심볼 |
|---|---|

| 검색에서 사용하는 필드 | `backend/struct4search/adapters/search/opensearch/native_hybrid.py` |
| Citation 계약 | `backend/struct4search/query/contracts.py` |
