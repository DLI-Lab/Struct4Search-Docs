# 데이터와 인덱스 구조 변경

색인 문서의 필드나 인덱스 매핑을 바꿉니다. 이 변경은 거의 항상 **인덱스를 새로 만드는 일**로 이어집니다.

## 무엇이 무효화되는가

| 바꾼 것 | 무효화되는 것 |
|---|---|
| 색인 문서에 필드 추가 | 기존 색인 문서. 새 필드가 비어 있습니다 |
| 기존 필드의 타입 변경 | 인덱스 매핑. 같은 인덱스에 섞을 수 없습니다 |
| 벡터 차원 변경 | 모든 벡터. 기존 벡터와 비교 불가 |
| 검색 단위 종류 추가 | 검색 질의와 점수 통합의 분기 |
| 청크 ID 구성 변경 | 검색 단위 ID 전부와 그것을 가리키는 모든 산출물 |

OpenSearch는 이미 만들어진 필드의 타입을 바꿔 주지 않습니다. 타입이나 차원을 바꾸면 **새 인덱스를 만들고 다시 색인**합니다.

## 새 인덱스로 넘어가는 절차

1. 매핑을 고칩니다.
2. 새 이름으로 인덱스를 만들고 코퍼스를 다시 색인합니다.
3. 새 인덱스로 검색·QA 평가를 돌려 기준선과 비교합니다.
4. 별칭을 새 인덱스로 옮깁니다.
5. 이전 인덱스는 검증이 끝난 뒤에 지웁니다.

별칭을 먼저 옮기고 검증하지 않습니다. 문제가 있을 때 되돌릴 자리가 사라집니다.

## 검색 단위 종류를 추가할 때

지금은 두 종류입니다 — `source`와 `retrieval_expression`. 세 번째를 넣으려면 다음을 함께 정해야 합니다.

- 그 단위가 원문 청크로 되돌아가는 링크를 갖는가.
- 검색에 걸렸을 때 점수를 어떻게 처리하는가.
- **답변에서 인용할 수 있는가.**

세 번째가 핵심입니다. 인용 가능한 것은 원문 청크뿐이라는 계약이 답변 Schema와 인용 정리에 걸려 있습니다. 새 단위를 인용 가능하게 만들려면 그 계약부터 다시 정해야 합니다.

## 되돌리기

| 상황 | 되돌리는 방법 |
|---|---|
| 별칭을 옮기기 전 | 새 인덱스를 지우면 끝입니다 |
| 별칭을 옮긴 뒤 | 이전 인덱스가 남아 있으면 별칭을 되돌립니다 |
| 이전 인덱스를 지운 뒤 | 되돌아가지 않습니다. 다시 색인해야 합니다 |

마지막 줄 때문에 이전 인덱스를 지우는 시점을 늦춥니다.
