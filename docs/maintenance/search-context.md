# 검색과 Context 수정

검색 후보 수와 최종 근거 수, 답변 예산을 바꿉니다. 색인에는 손대지 않습니다.

## 값 사이의 관계

이 값들은 따로 놀지 않습니다. 하나를 바꾸면 뒤가 따라 움직입니다.

| 값 | 현재값 | 무엇을 정하는가 |
|---|---:|---|
| `query.native_rrf.bm25_depth` · `dense_depth` | 50 | 채널별 후보 깊이 |
| `query.native_rrf.pagination_depth` | 50 | hybrid 요청 안의 후보 깊이 |
| `query.native_rrf.rrf_rank_constant` | 60 | RRF 상수 |
| `query.native_rrf.combined_depth` | 30 | OpenSearch가 돌려주는 후보 수 |
| `query.native_rrf.final_source_top_k` | 10 | 최종 근거로 쓰는 원문 청크 수 |
| `query.reader.generation.context_window_tokens` | 16384 | 답변 모델의 컨텍스트 창 |

```text
채널 깊이 50  →  통합 후보 30  →  최종 근거 10  →  Context  →  출력 예산
```

**채널 깊이를 줄이면** 통합이 볼 수 있는 후보가 줄어 최종 근거의 질이 떨어집니다.

**통합 후보를 줄이면** 검색표현을 원문 청크로 옮기고 중복을 정리한 뒤 근거가 10건에 못 미치는 질의가 생깁니다. 30은 그런 질의가 나오지 않도록 잡은 여유입니다.

**최종 근거 수를 늘리면** Context가 길어지고, 출력 예산은 컨텍스트 창에서 프롬프트가 쓰고 남은 자리이므로 답변이 쓸 자리가 줄어듭니다.

## 바꿀 수 없는 값

채널 깊이 50, 통합 후보 30, RRF 상수 60은 코드가 고정값으로 검사합니다. 최종 근거 수의 상한 10도 코드 상수입니다. 프로파일에 다른 값을 적으면 기동이 막힙니다.

**개별 파라미터를 조금씩 돌려 보는 방식으로 바꾸지 않습니다.** 이 값들은 서로 묶여 있어 하나만 움직이면 뒤에서 근거가 모자라거나 예산이 터집니다.

## 점수 통합 방식을 바꿀 때

점수 통합은 설정값이 아니라 정책 구현입니다([검색 결과 점수 통합](../query/score-integration.md)). 바꾸려면 정책을 교체해야 하며, 다음 계약을 깨지 않는지 먼저 확인합니다.

- 최종 순위는 원문 청크로만 구성됩니다.
- 검색표현 점수를 나누거나 더하지 않습니다.
- 같은 청크가 두 번 나오지 않습니다.
- 같은 입력이면 같은 결과가 나옵니다.

## Context 구성을 바꿀 때

근거 렌더링 형식을 바꾸면 답변 모델이 읽는 글이 바뀝니다. 특히 `· 인용 불가` 표시를 빼면 검색표현이 인용 후보처럼 보이게 됩니다. 실제 강제는 Schema가 하지만, 표시가 사라지면 모델이 그 규칙을 지킬 이유를 잃습니다.

## 바꾼 뒤 실행할 것

색인은 그대로이므로 재처리와 재색인이 없습니다. 대신 **검색 평가와 QA 평가를 모두** 다시 측정합니다. 검색 지표가 올라도 Context가 바뀌면 답변이 나빠질 수 있습니다([기준 성능과 회귀 판정](../testing/regression-gates.md)).
