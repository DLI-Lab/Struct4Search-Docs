# 모델 교체

파이프라인이 쓰는 모델을 바꾸고, 바뀐 만큼만 다시 처리합니다.

## 교체 대상

| 모델 | 쓰는 단계 | 설정 위치 |
|---|---|---|
| MinerU | 문서 파싱의 스캔·복합 페이지 | `configs/ingest-production.yaml` · `parser` |
| GLiNER | NER | `configs/ingest-production.yaml` · `ner` |
| Qwen | Metadata 생성 · KG 구축 · 검색표현 생성 | `configs/ingest-production.yaml` · `llm` |
| 임베딩 | 인덱싱과 질의 벡터 | `configs/ingest-production.yaml` · `index` |
| 답변 모델 | 답변과 출처 표기 | `configs/production.yaml` · `query.reader` |

## 변경 절차

1. 설정에서 모델 이름과 주소를 바꿉니다.
2. 서비스 정의(`configs/services/cold-services.yaml`)의 해당 서비스도 함께 맞춥니다.
3. 아래 재실행 범위만큼 다시 처리합니다.
4. 평가를 다시 측정합니다.

설정과 서비스 정의가 어긋나면 프로파일이 말하는 모델과 실제로 뜬 서버가 달라집니다. 두 곳을 함께 고칩니다.

## 모델별 확인 사항

**GLiNER** — `revision`까지 고정되어 있습니다. 모델을 바꾸면 `revision`도 함께 바꿔야 합니다. 같은 입력·코드·프로파일이면 같은 엔티티가 나와야 하기 때문입니다.

**임베딩** — 색인 벡터와 질의 벡터가 **같은 모델과 차원**이어야 합니다. 한쪽만 바꾸면 비교 자체가 성립하지 않습니다. 차원이 달라지면 인덱스를 새로 만들어야 합니다.

**Qwen과 답변 모델** — 구조화 출력을 지원해야 합니다. 프롬프트 정의가 호환 모델을 명시하고 있으므로 함께 확인합니다.

**MinerU** — 스캔·복합 페이지만 담당합니다. 디지털 PDF만 처리한다면 이 모델은 실행에 관여하지 않습니다.

## 재실행 범위

| 바꾼 모델 | 다시 도는 단계 | 재색인 |
|---|---|---|
| MinerU | 문서 파싱부터 전부 | 필요 |
| GLiNER | NER · KG 구축 · 검색표현 생성 · 인덱싱 | 필요 |
| Qwen | 해당 단계부터 인덱싱까지 | 필요 |
| 임베딩 | 인덱싱 | 인덱스를 새로 만듦 |
| 답변 모델 | 없음 | 없음 |

답변 모델만 바꾸면 색인은 그대로입니다. 검색 결과가 같으므로 QA 평가만 다시 재면 됩니다.

## 검증과 되돌리기

```bash
struct4search-smoke-e2e
```

문서 한 건으로 전체 경로가 도는지 먼저 확인한 뒤 평가를 돌립니다([검색과 QA 평가 실행](../testing/retrieval-qa.md)).

설정 값을 되돌리면 모델은 되돌아갑니다. 다만 **재색인한 인덱스는 되돌아가지 않으므로**, 인덱스를 새로 만드는 변경은 이전 인덱스를 지우기 전에 새 인덱스를 검증합니다.
