# 모듈 추가와 교체

파이프라인에 단계를 더하거나 기존 구현을 다른 것으로 바꿉니다.

## 두 가지 경우가 다릅니다

| 경우 | 하는 일 |
|---|---|
| 구현 교체 | 이미 있는 계약을 다른 구현으로 갈아 끼웁니다 |
| 단계 추가 | 새 계약과 산출물을 만들고 흐름에 끼워 넣습니다 |

앞의 경우가 훨씬 쉽습니다. 검색·답변 경로는 협력자를 전부 주입받도록 되어 있어, 계약만 지키면 조립 지점에서 바꿔 끼울 수 있습니다.

## 구현 교체

검색·답변 경로가 주입받는 계약은 다음입니다.

| 계약 | 하는 일 |
|---|---|
| `EmbeddingPort` | 질의를 벡터로 |
| `RetrievalStrategy` | 검색 후보를 가져오기 |
| `Reader` | 근거로 답변 생성 |
| `CitationNormalizer` | 인용 정리 |
| `SourceLinkResolver` | 출처 링크 생성 |
| `RetrievalPolicies` | 점수 통합 네 정책 묶음 |

교체 절차는 다음과 같습니다.

1. 해당 프로토콜을 구현합니다.
2. 조립 지점(`src/struct4search/bootstrap/composition.py`)에서 새 구현을 주입합니다.
3. 계약 테스트를 돌립니다.

질의 서비스는 순서만 소유합니다. 외부 클라이언트를 만들지도, 순위를 다시 매기지도, 점수를 정규화하지도 않습니다. **새 구현이 그 경계를 넘으면 계약 위반입니다.**

## 단계 추가

인덱싱 단계는 `src/struct4search/ingest/stages/` 아래에 있고 오케스트레이션이 순서를 정합니다. 새 단계를 넣을 때 지켜야 할 것은 다음입니다.

- **입력과 출력을 계약으로 선언합니다.** 앞 단계의 산출물을 읽고 자기 산출물을 문서별 디렉터리에 씁니다.
- **같은 입력이면 같은 출력을 냅니다.** 두 번 돌려도 결과가 같아야 재개가 성립합니다.
- **실패를 삼키지 않습니다.** 부분 결과를 완료로 보고하면 완료 수가 실제보다 나은 상태를 말하게 됩니다.
- **설정 키를 스키마에 선언합니다.** 선언 없는 키는 로드가 거부합니다.

## 무엇을 함께 고쳐야 하는가

| 대상 | 이유 |
|---|---|
| 설정 스키마 | 새 키를 선언해야 로드됩니다 |
| 실행 프로파일 | 값을 넣습니다 |
| 조립 지점 | 새 구현을 주입합니다 |
| 완료 판정 | 새 산출물이 완료 조건에 들어가는지 정합니다 |
| 테스트 | 계약을 고정합니다 |
| 문서 | 해당 단계 페이지와 [변경 지점 찾기](change-map.md) |

## 재실행 범위와 되돌리기

새 단계나 교체한 구현이 산출물을 바꾸면 **그 단계부터 인덱싱까지 다시 처리하고 재색인**합니다. 검색 경로만 바꿨다면 재색인은 필요 없습니다.

되돌리려면 조립 지점에서 이전 구현을 다시 주입합니다. 산출물 형식이 바뀌었다면 그 단계부터 다시 처리해야 이전 상태로 돌아갑니다.
