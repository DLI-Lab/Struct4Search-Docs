# 설정 수정

실행 프로파일의 값을 바꾸고, 잘못된 설정이 실행 전에 걸리도록 합니다.

## 프로파일 두 개

| 프로파일 | 담당 |
|---|---|
| `configs/ingest-production.yaml` | 문서 인덱싱 파이프라인 |
| `configs/production.yaml` | 검색·답변 파이프라인 |

프로파일은 `extends`로 다른 파일을 이어받을 수 있고, 경로 값은 기계별 정의에서 채워집니다. 같은 프로파일을 실행 진입점마다 다르게 쓰지 않습니다 — 프로파일이 다르면 뜨는 서버도 달라집니다.

## 로드가 거부하는 것

설정은 실행 전에 검사받습니다. 다음은 로드 자체가 실패합니다.

| 상황 | 결과 |
|---|---|
| 선언되지 않은 키 | 거부 |
| 타입이 맞지 않는 값 | 거부 |
| 고정 리터럴과 다른 값 | 거부 |
| 프로파일 스키마 버전 불일치 | 거부 |
| 프롬프트 해시 불일치 | 거부 |
| 검색 파이프라인 해시 불일치 | 거부 |

오타가 조용히 무시되지 않습니다. 잘못된 설정으로 몇 시간을 돌린 뒤에 발견하는 것보다 낫습니다.

## 계산되는 값을 적지 않습니다

일부 값은 다른 값에서 **계산됩니다.** 예를 들어 답변의 출력 예산은 컨텍스트 창에서 프롬프트가 쓰고 남은 자리이지 설정값이 아닙니다.

계산되는 값을 프로파일에 손으로 적으면 두 값이 어긋나는 순간이 옵니다. 설정에 없는 값은 계산되는 값입니다.

## 고정 리터럴

몇몇 값은 설정으로 바꿀 수 없습니다.

| 값 | 고정 위치 |
|---|---|
| `chunking.max_tokens` 400 · `overlap_tokens` 40 | 설정 스키마 |
| `chunking.strategy` | 설정 스키마 |
| 검색 채널 깊이 50 · 후보 30 · RRF 상수 60 | 검색 어댑터 |
| 최종 근거 상한 10 | 검색 정책 |

이 값을 바꾸려면 코드 변경이 함께 필요합니다. 설정만 고치면 기동이 막힙니다.

## 키를 새로 추가할 때

1. 설정 스키마에 키를 선언합니다. 선언 없는 키는 거부됩니다.
2. 타입과 허용 범위를 함께 정합니다.
3. 프로파일에 값을 넣습니다.
4. 그 값을 읽는 코드를 연결합니다.

## 변경 절차와 확인

값을 바꾼 뒤에는 프로파일을 한 번 로드해 봅니다. 인덱싱 설정을 바꿨다면 [변경 지점 찾기](change-map.md)에서 재처리 범위를 확인하고, 검색 설정을 바꿨다면 [검색과 Context 수정](search-context.md)의 값 관계를 먼저 봅니다.
