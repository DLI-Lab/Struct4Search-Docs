# 용어 사전

문서에서 반복해 나오는 말을 모았습니다.

## 파이프라인 단계

| 용어 | 뜻 |
|---|---|
| 문서 파싱 | PDF를 읽어 IDR로 만드는 단계 |
| 원문 청킹 | 본문을 400토큰 단위로 잘라 검색 단위를 만드는 단계 |
| NER | 문서에서 엔티티를 뽑는 단계 |
| Metadata 생성 | 원문 청크를 근거로 도메인 18종을 뽑는 단계 |
| KG 구축 | 관계를 뽑아 문서 지식그래프를 만드는 단계 |
| 검색표현 생성 | 지식그래프와 Metadata로 검색용 문장을 만드는 단계 |
| 인덱싱 | 검색 단위를 OpenSearch에 저장하는 단계 |
| 질의 처리 | 질의 텍스트와 임베딩 벡터를 만드는 단계 |
| Hybrid 검색 | BM25와 Dense를 함께 수행하는 검색 |
| RRF 통합 | 두 채널의 순위를 합쳐 후보를 만드는 단계 |
| 검색 결과 점수 통합 | 검색표현 점수를 원문 청크로 옮겨 최종 근거를 고르는 단계 |
| LLM Context 구성 | 답변 모델이 받을 입력을 만드는 단계 |
| 답변과 출처 표기 | 모델이 주장과 인용을 내는 단계 |
| 답변 후처리 및 원본 출처 연결 | 인용을 정리하고 문서·페이지로 잇는 단계 |

## 데이터

| 용어 | 뜻 |
|---|---|
| IDR | 파서 종류와 무관하게 같은 형태를 갖는 표준 문서 표현 |
| 원문 청크 | 문서에서 그대로 잘라낸 텍스트. `fc_`·`ruf_` |
| 검색 단위 | 색인에 들어가는 단위. 원문 청크와 검색표현 두 종류 |
| 검색표현 | 문서의 지식으로 다시 쓴 검색용 문장. `rte_` |
| 엔티티 | 문서에서 뽑은 개체. `e_` |
| Triple | 주체·관계·대상 세 값으로 된 관계. `kgtr_` |
| 문서 지식그래프 | 문서 하나의 엔티티와 관계를 모은 그래프 |
| Metadata | 문서의 도메인 정보 18종. 저장 키는 `domain_` 접두사 |
| claim | 답변의 주장 문장 하나와 그 인용 |
| Citation | 답변이 인용한 원문 청크. 원문 청크만 가능 |

## 검색

| 용어 | 뜻 |
|---|---|
| BM25 | 어휘가 얼마나 겹치는지로 매기는 검색 |
| Dense | 벡터의 가까움으로 매기는 검색 |
| RRF | 여러 채널의 순위를 합치는 방식 |
| search pipeline | OpenSearch가 검색 결과를 후처리하는 설정 |
| `unit_kind` | 검색 단위의 종류. `source` 또는 `retrieval_expression` |
| Top-30 | RRF가 돌려주는 후보 수 |
| Top-10 | 답변 근거로 쓰는 원문 청크 수 |
| 투영 | 검색표현의 점수를 연결된 원문 청크에 옮기는 일 |
| Max Score | 한 청크가 받은 점수 중 가장 높은 값 |

## 실행

| 용어 | 뜻 |
|---|---|
| 프로파일 | 파이프라인 동작을 정하는 YAML 설정 |
| 서비스 정의 | 띄울 모델·검색 서버를 적은 파일 |
| 워크플로 ID | 프로파일·출력 경로·문서 목록의 해시. 실행의 신원 |
| 완료 기록 | 문서 하나가 끝났음을 남기는 산출물 |
| 부분 완료 | 단계 일부만 끝난 문서. 완료 수에 들어가지 않음 |
| 재색인 | 인덱스를 새로 만들고 코퍼스를 다시 넣는 일 |
| 평가셋 릴리스 | 문서·질의·정답을 묶어 고정한 자산 |
| 기준선 | 변경 전후를 비교하는 기준 측정값과 그 조건 |

## 코드에만 있는 이름

문서 본문에서는 쓰지 않지만 코드를 읽을 때 마주치는 이름입니다.

| 코드 이름 | 문서에서 부르는 이름 |
|---|---|
| `F400` · `f400` | 원문 청크 |
| `G2` | 검색표현 |
| `V3` | KG 구축의 청크 묶기 |
| `RTE` · `rte_` | 검색표현 |
| `cold` | 인덱싱 실행 |
| `reader` | 답변 모델 |
| `projection` | 점수 투영 |
